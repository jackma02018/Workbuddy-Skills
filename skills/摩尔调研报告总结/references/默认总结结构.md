# 默认总结结构（未提供总结模板时采用）

当用户未提供「调研报告总结模板」.txt 时，按以下固定结构产出纯文本 TXT。标点严格按下述（含全/半角冒号差异），章节标题、字段名、编号、顺序不得改动。

```
一、调研基本信息
[YYYY 年 M月D 日]，与[摩尔元数售前顾问]一起到[客户（地点）]客户现场调研，采用[现场会议访谈/车间走访]方式沟通，客户[部门（负责人）]参与访谈；[覆盖 X 个车间、Y 个仓库及研发实验线]。

二、项目现状：
企业生产产品：[产品类别]，[应用领域]；[所处阶段与生产模式]。
现有 [ERP 等系统]；[系统现状]。
当前计划、生产、质量、工艺、仓库均依靠 Excel、纸质单据线下管理，[条码化/系统现状]，无 MES 系统承载生产全流程数字化管控。

三、核心业务需求痛点:

1、生产计划：[计划模式与线下断点、缺料/锁定/齐套机制缺失的业务后果]
2、仓库：[WMS 现状、条码化、收发单据闭环与账实不符风险]
3、物料防错:[防错手段、追溯分级、挪料串用与账实不符风险]
4、品质管理:[检验/ECN/8D/NCR 记录与追溯统计难点]
5、设备管理:[保养/维修/点检/仪器校验台账与可追溯难点]
6、现场可视化与异常预警:[看板缺失、分级预警/Andon 缺失、异常通知无闭环]

四、竞争对手：[现有系统供应商/ERP 厂商]；
五、下一步计划
[出具基础方案 / 分享脱敏案例 / 提供服务器配置等具体待办与责任方、时间]
```

## 字段映射说明（从调研报告 docx 抽取）

| 模板字段 | 报告对应章节 |
|---|---|
| 一、调研基本信息 | 一、项目基本信息（项目名称/调研人/调研时间/调研方式/调研地点/访谈部门/项目负责人） |
| 二、项目现状：企业生产产品 | 二、项目背景（2.1 公司背景 / 2.2 主要产品） |
| 二、项目现状：现有系统 | 三、项目调研 3.2 IT 系统现状与集成（ERP/钉钉） |
| 二、项目现状：线下管理 | 三、项目调研各子节「现状」共性（计划/生产/工艺/品质/设备/仓库均 Excel/纸质） |
| 三、1 生产计划 | 3.3 计划 PMC |
| 三、2 仓库 | 3.8 仓库 WMS |
| 三、3 物料防错 | 3.4 生产 / 3.8 仓库（防错、追溯、挪料串用） |
| 三、4 品质管理 | 3.6 品质 |
| 三、5 设备管理 | 3.7 设备工程 |
| 三、6 现场可视化与异常预警 | 3.9 车间分组细化（看板、Andon、钉钉异常单） |
| 四、竞争对手 | 报告中「现有 ERP 厂商 / 在用系统供应商」（如金蝶云星辰）；无依据则标「本次报告未载明」 |
| 五、下一步计划 | 五、后续行动计划（表7 待办 + 责任人 + 时间） |
