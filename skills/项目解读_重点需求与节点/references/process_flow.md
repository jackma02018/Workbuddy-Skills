# 执行流程详解（顺序与依赖）

本文件是 SKILL.md「四、执行流程」的展开。每一步给出：输入 / 动作 / 输出 / 判断标准 / 常见错误。

## 总依赖图（DAG）

```
        ┌─ S0.1 确认输入（资料路径 / 模板 / 客户简称 / 日期 / 深度）
S0 准备 ─┤
        └─ S0.2 搭建隔离 venv（python-pptx + openpyxl + python-docx）  ← 一次性，跨项目复用

S1 资料解析 ── S1.1 列举+按类型分组 → S1.2 读核心源文档 → S1.3 抽工艺/节点/基线 → S1.4 提炼三部分
S2 模板解析 ── S2.1 potx→pptx 修 content-type → S2.2 解析版式/占位符 → S2.3 记录主题色/字体
            （S1 与 S2 互不依赖，可并行；均只依赖 S0）

S3 渲染生成 ── 强依赖 S1(内容) ∩ S2(版式)
S4 校验     ── 依赖 S3
S5 归档     ── 依赖 S4 通过
```

**依赖结论（MECE）：**
- S0 是 S1、S2 的共同前置。
- S1 与 S2 并行，二者汇合于 S3。
- S3 → S4 → S5 严格串行。

---

## S0 准备与环境（无前置）

### S0.1 确认输入
- **输入**：用户给出的资料文件夹 / 模板路径 / 客户简称 / 归档日期 / 深度。
- **动作**：缺失则索取；`client` 可从路径或资料推断，但必须显式回告推断结果。
- **判断**：五项输入齐了才能进 S1/S2。

### S0.2 搭建隔离 venv（一次性）
- **动作**：`python -m venv .../envs/default`；装 `python-pptx openpyxl python-docx`。
- **判断**：`import pptx` 成功即可。此后所有会话复用，不必重复装。

---

## S1 资料解析（依赖 S0.1）

### S1.1 列举与分组
- **动作**：遍历 `source_path` 全部文件，按 文档(docx/txt/pdf) / 表格(xlsx/csv) / 图片(jpg/png) / 音视频 分组。
- **输出**：文件清单（带相对路径）。
- **常见错误**：只读主文档，漏掉 xlsx 与照片里的关键基线。

### S1.2 读取核心源文档
- **动作**：**完整读取，不抽样**。docx/txt 抽文本；xlsx 逐 sheet 读；图片逐张读（现场照片、设备铭牌、看板是事实来源）；若有智能纪要/录音转写也要读。
- **输出**：原始事实集合。
- **可并行**：多份文档相互独立，可并发读取。
- **常见错误**：把客户自述痛点当事实直接抄（事实与客户判断要分开记）。

### S1.3 抽取工艺与节点细节
- **动作**：从事实中抽：① 生产制程顺序（IQC→SMT→DIP→组装→老化测试→包装→出货）；② 关键约束（如倒扣模式、72h 过炉时效、一阶 BOM）；③ 各节点数据基线（产线数、日产能、仓面积、OEE、CPK）；④ 判定标准（CPK≥1.33 等）。
- **输出**：工艺/节点事实卡。
- **判断**：每条带数值或原句，不带形容词。

### S1.4 提炼三部分
- **动作**：
  1. **重点需求 7–10 条**：排序维度 `客户关注度 × 业务价值 × 落地可行性`；每条带可检验的判定/量化说明；**不写 P0/P1/P2**（如要体现优先级，用文字理由）。
  2. **主要流程**：按制程顺序排节点流，每节点写动作/约束。
  3. **重要节点**：表格 `管控节点 | 管控内容 | 判定标准`，每个节点回答"在哪卡 + 靠什么判断"。
- **输出**：结构化三部分（即 content.json 的 requirements / process / nodes / todos / conclusion）。
- **常见错误**：需求平铺无排序；节点只有"管控内容"没有"判定标准"。

---

## S2 模板解析（依赖 S0.1 模板路径；可与 S1 并行）

### S2.1 potx→pptx 修正 content-type
- **动作**：解压 .potx，把 `[Content_Types].xml` 的 `...template.main+xml` 改为 `...presentation.main+xml`，另存临时 .pptx。
- **原因**：python-pptx 按 content-type 判定，模板默认打不开。
- **判断**：能 `Presentation(tmp)` 成功即为通过。

### S2.2 解析版式与占位符
- **动作**：列出各版式名称、占位符索引/类型（`scripts/inspect_template.py`）。
- **输出**：版式映射表（封面/内容/仅标题等）。

### S2.3 记录主题色与字体
- **动作**：从 theme1.xml 读 accent 色与默认字体（微软雅黑）。
- **输出**：调色板常量（写入渲染脚本）。
- **判断**：渲染用的颜色/字体须与模板一致，否则成品"跳色"。

---

## S3 渲染生成（强依赖 S1 ∩ S2）

### 步骤
1. 复制模板临时副本（已修 content-type）。
2. **彻底清示例页**：删 `sldIdLst` 全部引用 + `drop_rel` + 丢弃孤儿 `SlidePart`（否则报 Duplicate name）。
3. 按 6 版式渲染：封面(标题幻灯片) / 重点需求(标题和内容) / 主要流程(仅标题) / 重要节点(仅标题) / 待确认(标题和内容) / 结论(仅标题)。
4. 重点需求用 `enumerate` **自动编号**（增删条目自动重排）；副标题独占一段，避免与首条粘连。
5. 套用模板主题色/字体；流程节点框宽度按数量自适应；节点表格显式行高防挤压。

### 判断标准
- 全部形状在 13.33×7.5″ 画布内（几何安全）。
- 编号连续、无 P0/P1/P2、无 ①。

---

## S4 校验（依赖 S3）

- **① 包完整性**：`zipfile.testzip()` 通过，全部 xml 良构。
- **② 几何溢出**：扫描所有 shape，越界即报警（`scripts/verify_deck.py`）。
- **③ 内容抽查**：重点需求页编号连续、无优先级标注、缩写保留、待确认项未藏正文。
- **常见错误**：声明完成但未验溢出 → 交付即返工。

---

## S5 归档与 WPS 占用处理（依赖 S4 通过）

- **命名**：`YYYYMMDD_客户简称_重点需求.pptx`，落到**源资料同目录**（不新建文件夹）。
- **WPS 锁检测**：若同目录存在 `~$YYYYMMDD_客户简称_重点需求.pptx` → 说明目标被 WPS 占用，**另存递增版本** `_v2/_v3...`，**不覆盖、不强制删除、不结束用户进程**。
- **说明**：交付时告知用户"基础文件名被占用已另存 _vN；关闭 WPS 后可重跑脚本覆盖回原名"。
- **常见错误**：直接覆盖被占用的文件导致 WPS 报错或文件损坏。
