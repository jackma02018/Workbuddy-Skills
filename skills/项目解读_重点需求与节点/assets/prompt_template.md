## 任务：项目解读 → 重点需求与关键节点 → 套模板交付 PPT

请使用技能 `项目解读_重点需求与节点` 完成以下任务。

### 一、输入要求（必填，缺则先索取，不得编造）
- **资料文件夹**：`<E:\02跟进项目\xxx项目资料文件夹>`（含调研报告 docx/txt、调研计划 xlsx、客户资料/照片、纪要等全部资料）
- **模板**：`<E:\02跟进项目\摩尔方案模板.potx>`（默认此路径，如不同请给路径）
- **客户简称**：`<如"旺达电子">`（用于标题与文件名，用简称不用全称）
- **归档日期**：`<YYYYMMDD>`（默认今天）
- **深度**：standard（需求 7–10 条）/ deep（每条附根因+数据基线）

### 二、执行流程（按技能固定顺序，勿跳步）
1. **准备**：确认输入；用隔离 venv（`C:\Users\majunpeng\.workbuddy\binaries\python\envs\default`）的 python-pptx。
2. **资料解析**：完整读取文件夹全部资料 → 提炼三部分：
   - **重点需求** 7–10 条（按 `客户关注度 × 业务价值 × 落地可行性` 排序，每条带可检验的判定/量化说明）
   - **主要流程描述**（按生产制程顺序：IQC→SMT→DIP→组装→老化测试→包装→出货，节点化）
   - **重要节点描述**（表格三列：`管控节点 | 管控内容 | 判定标准`，每节点回答"在哪卡 + 靠什么判断"）
3. **模板解析**：potx 修 content-type 后解析版式/占位符/主题色字体（用 `scripts/inspect_template.py`）。
4. **渲染生成**：把三部分写入 `content.json`，运行 `scripts/build_deck.py` 套模板生成 6 页 PPT。
5. **校验**：运行 `scripts/verify_deck.py`，确认包完整性、无溢出、编号连续、无 P0/P1/P2、缩写保留、待确认项未藏正文。
6. **归档**：命名 `YYYYMMDD_客户简称_重点需求.pptx` 落源资料同目录；若 `~$` 锁文件存在（WPS 占用）则另存 `_vN`，不覆盖/不杀进程。

### 三、输出格式
**交付物**：单文件 PPT（6 页）：封面 → 一、重点需求 → 二、主要流程描述 → 三、重要节点描述 → 四、待确认事项 → 五、结论与建议。
**附带（可选）**：`YYYYMMDD_客户简称_依据说明与待确认清单.md`，列每条需求的原始依据与待确认项。

### 四、硬约束（必须遵守）
- 凡资料无依据的数字，一律标 **「待确认」**，禁止估算当事实。
- 每条需求/节点必须**可检验、可量化或有明确判定标准**，禁止"加强管理/提高意识"类空泛表述。
- 行业缩写（SMT / BOM / ERP / FIFO / ECN / Andon / IQC / SPC / CPK …）**保留原文**。
- 重点需求**不使用 P0/P1/P2 标注**；编号由脚本自动生成（增删条目自动重排）。
- 副标题与首条需求须分段，不粘连。
- 交付前必须做校验并逐项报告。
- 源文件被 WPS 占用时，另存递增版本，**绝不覆盖、不强制删除文件、不结束用户进程**。

### 五、完成判据
- 校验清单 7 项全过（完整性/无溢出/编号连续/无优先级标注/缩写保留/命名归档/锁处理）。
- 向用户汇报：生成路径、是否触发 WPS 版本递增、待确认项数量、有无需用户补充的致命缺失。
