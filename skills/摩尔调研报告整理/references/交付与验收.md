# 交付与验收操作手册

## 一、命名与版本细则

| 场景 | 文件名 | 页脚版本 |
|---|---|---|
| 首次成稿 | `<客户简称> MES 系统建设现场调研报告_<编制日期YYYYMMDD>.docx` | V1.0 |
| 用户提出内容修订，可写回原文件 | 同名覆盖（改前备份） | V1.1 / V1.2 … |
| 原文件被 WPS/Word 独占，或用户要保留历史版 | `<原名>_修订版.docx`，同目录交付 | V1.1 或沿用 V1.0（按用户口径） |
| 用户指定文件名 | 以用户指定为准，仍需满足「客户简称 + 报告类型 + 日期」可识别性 | 按用户指定 |

- 客户简称取项目目录名或用户明确给出的名称；**不擅自补「有限公司」**，也不在文档里解释命名依据。
- 页脚编制日期必须与文件名日期一致（文件名 `20261105` ↔ 页脚 `2026-11-05`）。
- 交付目录**只留成品**；`_*.py`、`_*.txt`、`__pycache__`、临时副本一律清理。

## 二、页脚规范

```
编制：摩尔元数 MOM 售前顾问组　|　编制日期：YYYY-MM-DD　|　版本：V1.0　|　第 N 页
```

- 四要素（编制 / 编制日期 / 版本 / 页码）缺一不可；页码 `第 N 页` 必须是 Word `PAGE` 域，不是硬编码数字。
- **不得**包含「依据：…」「资料来源：…」「数据来源：…」等字段（本次已从页脚删除）。
- 生成方式：新增 `word/footer1.xml`，在 `word/document.xml` 的 `<w:sectPr>` 加 `<w:footerReference>`，并同步 `[Content_Types].xml` 的 Override 与 `word/_rels/document.xml.rels` 的 Relationship。

## 三、验收操作

```bash
C:/Users/majunpeng/.workbuddy/binaries/python/versions/3.13.12/python.exe \
  "C:/Users/majunpeng/.workbuddy/skills/摩尔调研报告整理/scripts/verify_report.py" \
  "<报告.docx 绝对路径>"
```

脚本输出三档：
- `PASS` — 该项通过；
- `WARN` — 非阻断项，需在交付说明里如实告知。常见的 3.9 称谓消歧：3.9 正式标题固定为「**车间分组细化**」，若检出范本遗留称谓「其它管理（总）」会报 WARN，新报告须统一为「车间分组细化」；基线件本身存在这处历史遗留，技能在复现时已加约束消除。
- `FAIL` — 阻断项，**必须修到全绿才能交付**。

退出码：`0` = 无 FAIL；`1` = 存在 FAIL。

验收 10 类（对应 SKILL §8）：结构 / 三段式 / 表格 / 措辞红线 / 元说明 / 编号与附录 / 页脚 / 术语 / 包完整性 / 文件规范。

**包完整性额外手动确认**：所有 `.xml`、`.rels` 用 `xml.etree.ElementTree.fromstring` 解析通过；`word/footer1.xml` 存在且 `footerReference` 在；`[Content_Types].xml` 与 rels 均含 footer1.xml。

**交付说明必须如实包含**：
- 本机是否做过 Office/WPS 端渲染验收；若只做了 XML 级校验，明确写「未做 Word/WPS 端渲染验收」。
- 改前备份路径。
- 若因文件占用交付了 `_修订版`，说明原文件路径与后续覆盖方式。

## 四、本机环境常见陷阱（按发生频率排序）

| # | 陷阱 | 处置 |
|---|---|---|
| 1 | 原文件被 `wps.exe` / `WINWORD.EXE` 独占，`save_file` 报 `file is occupied`，写入抛 `PermissionError [WinError 5]` | **不要结束用户进程**；另存 `_修订版.docx` 交付，提示用户关闭后再覆盖 |
| 2 | `save_file` 只写 Temp 下 staging 文件，磁盘原文件落后一版 | 每次保存后核对磁盘 mtime + 关键词残留；必要时 `shutil.copyfile(最新staging, 原路径)` |
| 3 | 替换字符串带前导空格 / 分隔符，匹配失败（如 ` / 供应商方案与行业案例演示`） | 用整个单元格文本完整匹配；替换后检查残留计数 |
| 4 | 批量删 `[E-xxx]` 后遗留 `。 `、悬空 ` / `、半截逗号 | 删除后扫描 `。 `、`不是产能数据，` 等，收束标点 |
| 5 | 删附录后自检清单仍引用「证据索引」「证据编号均连续」 | 按 客户可见性红线 §四 同步改写（1）（2）（3）（4）（5） |
| 6 | 本机无 python-docx、pip 装不上 | 标准库 `zipfile` 复用范本 styles.xml/theme，只替换 document.xml |
| 7 | bash 的 `cd`/`ls`/`cp`/`head` 被 shim 破坏 | 一切用 Python 绝对路径执行，文件操作走 `os` / `shutil` |
| 8 | 表格单元格文本被 `<w:t...>` 正则误匹配到 `<w:tcPr>` / `<w:tcW>` | 用严格正则 `<w:t(?:\s[^>]*)?>(.*?)</w:t>`，不要用 `<w:t[^>]*>` |
| 9 | 范本示例数字（8 条线、日产 5 万只、年 1500 万只等）被误抄 | 范本只取骨架与字段，数字一律来自本次资料 |
| 10 | 修订后未重新跑验收 | 每轮修改后重跑 `verify_report.py`，并核对磁盘文件而非仅看编辑器内存 |

## 五、交付回复的最小信息集

1. 交付物绝对路径（若交付修订版，同时给原文件路径与占用原因）。
2. 本轮做了什么（成稿 / 删除了哪几处 / 中性化了哪些字眼）。
3. 验收结果（8 表、五章、11 组三段式、7 条自检、页脚、禁用词 0、XML 通过）。
4. 需用户确认的「资料未载明」项（只在必要时列，且不写成文档内元说明）。
5. 备份路径与 Office 端渲染验收状态说明。
