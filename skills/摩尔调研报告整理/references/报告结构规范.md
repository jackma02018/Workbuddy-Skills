# 报告结构规范（摩尔范本五章骨架）

> 本文件是「摩尔调研报告整理」技能的结构权威口径。字段与表头沿用《摩尔调研报告模板.docx》，行数按实际资料扩展。
> 目标成果基线件实测：8 张表、11 个三段式子节、5 条结论摘要、13 条行动计划、7 条自检。

## 一、整体顺序（固定，不可增删章）

```
标题：XX MES 系统建设现场调研报告
调研结论摘要（不编章号，5 条）
一、项目基本信息
二、项目背景
三、项目调研
四、实施范围与边界建议
五、后续行动计划
附：术语约定（不编章号）  ← 表，不是章
文末自检清单（不编章号，7 条）
页脚：编制 / 编制日期 / 版本 / 页码
```

**禁止出现的章节**：附：证据索引、编制说明、资料来源说明、改稿记录、项目总结、版本变更表。

> 基线行数是参照，不是硬指标：**行数按实际资料扩展，不凑数编行**。资料没写的字段填「本次资料未载明」。

**表1 字段值口径**
- 项目名称：`<客户简称> MES 系统建设项目`，不擅自加「有限公司」，不写命名依据的括注。
- 调研人：按可确认的岗位/团队填写，不指派姓名。
- 调研时间：`YYYY 年 M 月 D 日` 或加总起止时段；**不拆分会场分时段**。
- 调研方式：只写客户现场实际调研动作（现场会议访谈 / 车间走访 + 走访范围）；**不写供应商方案与行业案例演示**。
- 调研地点：写到可核验的厂区/园区层级即可；**不加门牌地址、园区提供空间等解释性括注**。
- 访谈部门：按岗位/部门归并；客户方与摩尔元数侧分列。
- 调研方向：本期涉及的模块与接口方向，术语首次出现给中文全称。
- 项目负责人：写客户方可确认的对接角色；**不写「摩尔元数侧项目负责人本次资料未载明」**。

**表7 口径**：责任人按可确认岗位/团队填写；时间用可核验阶段锚点，无确切日期时标注「具体日期本次资料未载明」；每行两列都不得为空。

## 四、部门三段式模板（3.1—3.11 每节必用）

```
现状：<一句结论，概括本节客观事实>
• <谁 / 哪个环节 / 用什么工具 / 频率或数量>
• ……

需求：<一句结论，概括本节需交付的能力>
• <触发条件>…，输出字段为…，输出结果为…（可验收）
• ……

痛点：<一句结论，如「均为机制缺失导致的业务后果，不作形容词评价。」>
• 缺少 <X> 机制 → <具体业务后果>
• ……
```

| 段 | 必须 | 禁止 |
|---|---|---|
| 现状 | 客观事实：主体、环节、工具、频率/数量 | 评价、推断、外部基准、证据编号标注 |
| 需求 | 触发条件 / 卡控点 / 数据字段 / 输出结果 | 「提升效率」「加强管控」「优化流程」类空话 |
| 痛点 | 「缺少 X 机制 → 业务后果」句式 | 形容词堆砌、把机制写成人的失误 |

## 五、术语约定表（14 条，逐条沿用）

| 术语 | 中文全称 | 本报告用法 |
|---|---|---|
| MES | 制造执行系统（Manufacturing Execution System） | 正文首次出现给中文全称 |
| MOM | 制造运营管理（Manufacturing Operations Management） | 供应商交付口径，QMS 内置于 MOM 平台 |
| WMS | 仓储管理系统（Warehouse Management System） | 统一写法，不写作「库房系统」 |
| QMS | 质量管理系统（Quality Management System） | 统一写法 |
| IOT | 物联网（Internet of Things） | 本期指测试数据文件接入，非 PLC 数采 |
| ECN | 工程变更通知（Engineering Change Notice） | 统一写法；资料中 ECN/ECM/DCN 等异写统一为 ECN |
| ECR | 工程变更申请（Engineering Change Request） | 资料未出现时注明「后续方案引用时沿用本写法」 |
| SOP | 标准作业指导书（Standard Operating Procedure） | 统一写法 |
| Andon | 安灯（Andon，现场异常呼叫与响应机制） | 统一写法 |
| SPC | 统计过程控制（Statistical Process Control） | 统一写法；是否本期范围按资料标注 |
| OEE | 设备综合效率（Overall Equipment Effectiveness） | 资料未出现时注明「后续方案引用时沿用本写法」 |
| IQC | 来料检验（Incoming Quality Control） | 统一写法 |
| SN | 产品序列号（Serial Number） | 统一写法 |
| PLM | 产品生命周期管理（Product Lifecycle Management） | 统一写法 |

> 客户专有缩写（如 FAO、8D、AP、IPO）按资料原样保留，不强行纳入本表。

## 六、文末自检清单 7 条（措辞随交付状态同步）

```
（1）结构对齐：五章（一至五）编号连续；2.1—2.3、3.1—3.11、4.1—4.2 子节连续；表1—表7 共 7 张主表，表头与字段沿用范本；另附术语约定表 1 张，不编号、不计入主表；「调研结论摘要」置于正文前且为 5 条，每章开头一句结论。
（2）证据可追溯：正文各小节不显示证据编号标注；报告所载事实与结论均与本次现场调研一致，未载明信息统一标注「本次资料未载明」。
（3）零编造数字：所有数字、人名、系统名、日期均取自本次现场调研与项目基本信息；范本中的产线数量与产能数字一律未采用；资料未载明字段统一标注「本次资料未载明」，不推算、不凑行。
（4）编号连续：章号、子节号、表号均连续无跳号；附录与自检清单不编章号，不破坏五章结构。
（5）部门不重复：按部门 MECE 独立成节；跨部门事项归 3.10、3.11，车间级共性管控归 3.9「车间分组细化」。
（6）无占位符：全文未出现任何模板占位符或待填字段；「本次资料未载明」为证据状态标注，不是占位符；「未划分产线（车间制）」为资料事实。
（7）行动计划含责任人与时间：表7 共 13 行，每行均填写责任人与预计完成时间；责任人按可确认岗位/团队填写，未载明姓名的不推断。
```

> 第（5）条里的 3.9 名称必须与章节标题一致；第（7）条的「13 行」按实际待办条数改写。
> **不得引用已删除的「证据索引」附录**，不得写「证据编号均连续无跳号」「同一事实只在一处陈述」等被删措辞。
