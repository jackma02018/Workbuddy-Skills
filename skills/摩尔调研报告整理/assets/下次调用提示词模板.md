# 下次调用提示词模板（可直接复制）

> 复制下方代码块到新对话即可复现同类报告整理。**所有 `【】` 包裹项必须按实际情况替换**；未提供的项保持原样会导致资料缺失或命名错误。
> 若本次是「修订已有报告」而非「从零成稿」，改用文末的【修订模式】模板。

## 成稿模式

```
请调用技能【摩尔调研报告整理】，把本次客户现场调研资料整理成一份可直接交付的 Word 调研报告。

【资料位置】：<调研资料目录绝对路径，例如 E:\02跟进项目\<项目文件夹>\售前资料\调研录音资料>
【范本文件】：<摩尔调研报告模板.docx 绝对路径>
【客户简称】：<按项目目录名或我指定的名称，不要擅自加「有限公司」>
【调研日期】：<YYYY 年 M 月 D 日，见资料；有多场次只给一个总时段>
【编制日期】：<YYYYMMDD，用于文件名与页脚>
【版本号】：<V1.0；若为既有报告修订，按实际递增，如 V1.1>
【目标成果基线】：<可选；填「与上次一致」或给出基线 docx 绝对路径，缺省用技能内 references/目标成果基线.md>
【输出目录】：<交付目录绝对路径，默认与资料目录同级>

硬性要求：
1. 严格按技能定义的五章骨架、7 张主表 + 1 张术语约定表、结论摘要 5 条、11 个部门三段式子节、文末自检清单 7 条成稿；表头字段沿用范本，行数按实际资料扩展。
2. 零编造：数字、人名、系统名、设备型号、日期只能来自本次资料；范本示例数字一律禁用；资料缺失写「本次资料未载明」，不推算、不凑行、不擅自补公司全称。
3. 客户可见性：文档任何位置（含表格、表注、附录、自检清单、页脚）都不得出现资料来源字眼、证据编号标注、「附：证据索引」章节、内部对话痕迹、以及技能 references/客户可见性红线.md 列出的元说明句；规则只用于编写，不写进正文。
4. 命名与版本：文件名《【客户简称】 MES 系统建设现场调研报告_【编制日期】.docx》；页脚四要素（编制 / 编制日期 / 版本 / PAGE 页码），不含「依据：」。
5. 交付前运行 scripts/verify_report.py 验收，全部 PASS（允许说明 WARN）后再交付；改前备份，交付目录不留中间文件；如实说明是否做过 Office/WPS 端渲染验收。
6. 输出完成后，按「技能定义要点 / 自动检查结果 / 需我确认的未载明项」三段简报。
```

## 修订模式（对已有报告做删除 / 中性化 / 版本更新）

```
请调用技能【摩尔调研报告整理】，对已有报告执行整理修订。

【报告路径】：<待修订 .docx 绝对路径>
【本次要删除或修改的内容】：<逐条列出精确字符串；不确定时写「按技能客户可见性红线全面净化」>
【是否同步修订自检清单】：是（默认）
【版本号】：<V1.1 或沿用 V1.0>
【输出方式】：<写回原文件 / 另存 _修订版.docx；若原文件被 WPS 占用，自动改为另存并告知>

要求：改前备份；删除后清理遗留空格与悬空分隔符；同步修订文末自检清单里对已删内容的引用；重跑 scripts/verify_report.py 全绿后交付；如实说明文件占用与渲染验收情况。
```

## 替换项说明

| 占位项 | 必填 | 说明 | 示例 |
|---|---|---|---|
| 【资料位置】 | 是 | 调研资料目录或文件集绝对路径 | `E:\02跟进项目\上海-上海爱欧光学MES项目-激光器-20261104\售前资料\调研录音资料` |
| 【范本文件】 | 是 | 摩尔调研报告模板 `.docx`，只取骨架与字段 | `…\售前资料\摩尔调研报告模板.docx` |
| 【客户简称】 | 是 | 项目目录名或指定简称，**不擅自补「有限公司」** | 上海爱欧光学 |
| 【调研日期】 | 是 | 写进表1；不分会场拆分时段 | 2026 年 11 月 4 日 15:38—17:03 |
| 【编制日期】 | 是 | `YYYYMMDD`，同时决定文件名与页脚日期 | 20261105 ↔ 2026-11-05 |
| 【版本号】 | 是 | 首次 V1.0；修订按次递增 | V1.0 / V1.1 |
| 【目标成果基线】 | 否 | 需要「与上次一致」时填路径 | 上海爱欧光学 MES 系统建设现场调研报告_20261105_修订版.docx |
| 【输出目录】 | 否 | 缺省与资料目录同级 | `…\售前资料` |
| 【报告路径】 | 修订模式必填 | 现有 docx | `<…>_20261105.docx` |

> 模板里的客户名、日期、路径仅为示例，**必须整段替换为本项目的真实值**，不得把示例数据带进新报告（零编造规则同样适用于调用参数）。
