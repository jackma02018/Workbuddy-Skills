# 发票批量重命名

把散乱的票据文件名统一成可检索、可核对的规范名。核心原则：**一切字段取自票面，绝不猜测**。

## 命名规范

```
<票面日期>_<票据类型>_<补充信息>_<金额>.<原扩展名>

20260911_火车票_苏州南站-福州站_407.50.pdf
20260819-20260820_网约车发票_江苏省苏州市+镇江市_86.20.pdf
20260913_退票_福州站-盛泽站_71.50.pdf
20260913_网约车行程_江苏省苏州市_60.42.pdf
```

| 字段 | 规则 |
|---|---|
| 日期 | **必须**从票面识别，格式 `YYYYMMDD`。跨多天用 `YYYYMMDD-YYYYMMDD`。**严禁用文件创建/修改时间，也严禁取文件名里的既有数字** |
| 类型 | `火车票` / `退票` / `网约车发票` / `网约车行程` |
| 补充 | 火车票/退票 = `出发站-到达站`（票面原始写法，含方位词如"南站""北站"）；网约车 = `省+市`（多城市用 `+` 连接，同省只标一次省名） |
| 金额 | 两位小数，不带货币符号 |

## 用法

```bash
# 先预览（默认，不改任何东西）
python rename_invoices.py --root "D:\00费用报销\未报销"

# 确认无误后再执行
python rename_invoices.py --root "D:\00费用报销\未报销" --execute --json plan.json
```

参数：
- `--root` 要遍历的目录（含子目录）。以 `_` 或 `.` 开头的目录自动跳过（`_临时处理`、`.workbuddy` 等）
- `--execute` 实际执行，不带则只预览
- `--json` 导出完整的原/新名对照 + 跳过原因

## OCR 路径（图片与扫描件）

覆盖范围：`.jpg/.jpeg/.png/.bmp/.webp/.tif/.tiff` 直接 OCR；
`.pdf` 若文本层不足 20 个字符（纯扫描件）自动渲染成位图再 OCR。
OCR 输出的 box 被换算成与 PDF `words` 同构的 `(x0, x1, y, text)`，后面 `lines_of`、`city_column`
等所有版式逻辑直接复用，不必为 OCR 单写一套解析。

**踩过的四个坑：**

1. **行聚合阈值必须随坐标尺度自适应。** PDF 的 y 是 pt（票据页通常几百），OCR 出来是像素坐标（数千），
   同一行的词间距被等比放大，用 PDF 的 `tol=3.5` 会把一行劈成多行。做法是当 `max(y) > 1000` 时取
   `tol = max(tol, max(y)/80)`。

2. **OCR 稳定丢失票面大号加粗站名的「站」字。** 实测 dpi 300/400/600 全一样 —— 提分辨率没用，
   不是分辨率问题。有效解是**二段式增强**：先在整页 OCR 里找到匹配 `[A-Z]\d{1,4}` 的车次，
   以它为中心向左右各扩 45% 页宽、上下留一条带，裁出来放大 2 倍再识别一次。
   这一步能把「苏州南 / 福州」还原成完整的「苏州南站 G1315 福州站」。
   注意 coords 要除以放大倍数再加裁剪偏移才能还原。

3. **车次可能夹在两站中间**（OCR 整行识别成「苏州南站G1315福州站」），也可能跟在末尾
   （PDF 文本层是「苏州南站福州站G1315」）。正则必须两种都支持：
   `(站A)\s*([A-Z]\d{1,4})?\s*(站B)\s*([A-Z]\d{1,4})?`，取 group(1) 与 group(3)。

4. **OCR 会插空格并把车厢号夹进日期与时间中间**，把 `…09:02开` 变成 `…02车10D号09: 02开`。
   乘车日期正则要给中间留余量：`日[^开]{0,20}?\d{1,2}:\s*\d{2}开`。

另外 `classify` 不能靠整串匹配「电子发票（铁路电子客票）」——OCR 会把它切碎。
改用特征词投票：`铁路电子 / 电子客票号 / 12306 / 车次 / 二等座 / 票价` 命中 ≥2 个即判为火车票。

## 关键实现要点（踩过的坑）

1. **火车票日期会被「开票日期」骗到。** 票面同时存在「开票日期:2026年09月15日」和乘车日「2026年09月11日09:02开」。必须用强模式
   `(20\d{2})年(\d{1,2})月(\d{1,2})日\s*\d{2}:\d{2}开`，
   只看 `\d{2}:\d{2}开` 之前的那个日期。否则会把处理当天当成乘车日。

2. **行程单的城市列会被 PDF 换行切成两半。** 文本层里"苏州"和"市"是两个 word 且 y 差约 8pt，`20260915_网约车行程_86.20.pdf` 因此识别不到城市。
   正解是**按坐标取列**：找到表头文字「城市」的 x 区间 `[x0, x1]`，收集 `y > 表头y` 且 `x0-8 <= word.x0 <= x1+8` 的所有词，
   再把 y 间距 ≤ 9pt 的词合并成一个单元格。按行拼接成整行文本再找「XX市」是行不通的，因为换行点正好落在词中间。

3. **网约车发票票面没有「城市」这一列**，只有行程单有。`60.42` 那张曹操发票连出行日期都没有。
   解法是**三重兜底链**，按优先级：
   1. 日期优先取**配套行程单**的行程起止日期（最贴近实际消费日）——配对键是 `(金额, 平台)`；
   2. 取不到的取发票自身的**出行明细日期**（滴滴发票有，曹操没有）；
   3. 最后退回**开票日期**（2026年09月15日），它同样是票面内容，符合规则。
   城市同理：行程单城市列 → 销方注册地所在市（`苏州市吉利优行电子科技有限公司` → 苏州市）。
   平台判定用全文关键词，顺序很重要——**先判曹操再判滴滴**：含 `曹操|吉利优行|优行` → 曹操，含 `滴滴` → 滴滴。
   （按「销方名称」正则取公司名会失败，因为购买方名称总是排在前面。）

4. **开票日期必须从坐标重组的行里取，不能用原生文本流。** `page.get_text("text")` 里
   「开票日期：」后面紧跟的是「购买方信息销售方信息…」，真正的日期被推到别处。
   必须 `lines_of(pages)` 后找含「开票日期」的行再套 `DATE_CN`。

5. **金额提取**：优先匹配 `（小写）¥(\d+\.\d{2})`；匹配不到时退回取全文最后一个 `¥xx.xx`。行程单用 `合计([\d.]+)元`。

6. **羁旅变量泄漏**：`build_plan` 的 for 循环里 `start`/`end` 必须显式初始化为 `None`，
   否则孤立发票会串用上一轮行程单的日期（曾导致 60.42 的票被安上 20260819-20260820 的日期）。

7. **同省多城市**只标一次省名，输出 `江苏省苏州市+镇江市` 而不是两个都写全。

## 幂等性验收

脚本是幂等的：对已按规范命名的目录重跑，结果应全部显示「相同」且 `改动 0 / 跳过 0`。
改完任何解析逻辑都必须复跑全量目录验证这一点，否则重跑会把已经正确的名字弄乱。
另外要单独测**孤立发票**（不带配套行程单）的场景，确认走兜底链而不是被跳过。

## 安全约定

- 这是操作个人报销目录，执行 `--execute` 前**先备份**：`shutil.copytree(src, backup, dirs_exist_ok=True)`
- 一律先跑预览给用户确认再执行
- 无法识别日期/金额/城市的文件**跳过**并写明原因，绝不臆造填充

## 已知限制

- OFD 目前不解析内容（未实现），会被扫到但因无文本而跳过；需要先转 PDF 才能处理
- 城市→省份靠内置字典 `CITY_PROVINCE`（已覆盖江苏/福建/浙江全部地级市）加 `cpca` 兜底，
  字典未命中且无 cpca 时只输出城市不带省
- 一份文件只输出一条记录；多笔行程不拆分成多个文件副本
- OCR 依赖运行较慢：模型首次加载约 5s，单页识别约 8s，大批量图片要有心理预期
- OCR 属于尽力而为，识别不全时按规则**跳过**而不是猜测补字

## 验收清单

改完任何解析逻辑，必须跑完这三项再交付：

| 场景 | 期望结果 |
|---|---|
| 全量 PDF 目录 | `改动 0 / 跳过 0`（幂等，重跑不乱改已正确的名字） |
| 单张票据图片 | 命名结果与同名 PDF 版完全一致（仅扩展名不同） |
| 无文本层的扫描件 PDF | 走 OCR 降级，结果同上 |

另外测一次**孤立发票**（不带配套行程单），确认走兜底链而不是被跳过。

> 曾踩过的坑：`build_plan` 里用 `os.path.relpath(dp, root).split(os.sep)` 判断目录是否以 `_`/`.` 开头，
> 但根目录的 rel 是 `"."`，`".".startswith(("."))` 恒为真，**会把放在根目录的文件全部漏掉**。
> 必须先判断 `rel == "."` 再决定要不要 split。
