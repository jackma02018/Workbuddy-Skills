# 摩尔结构化方案编写

**一句话定位**：把客户模糊的制造诉求，翻译成一条「现状 → 痛点 → 方案 → 价值」可落地、可量化、可辩护的方案链路，并直接产出企业级汇报用的矢量可编辑 PPT。

**核心资产**：`scripts/deck_kit.py`（版式引擎，26 个矢量图标 + 五套骨架）+ `scripts/build_deck.py`（内容 JSON → PPT，自带体检）+ `references/`（方法论与规范）。

  3. **方案价值字号加大**：KPI 数值与标签、价值主张句、价值带标题整体放大（如数值 13→15/16/17pt、主张 9.5→12pt），视觉更突出。

- **保留的原有能力**：五套骨架差异化、四模块四层链路、双视角方案、26 矢量图标、内容 JSON 与引擎解耦、版式体检、系统界面截图弹层（Step 3+）、行业基线、质量红线——全部不变。

## 一、功能定位（解决什么问题）

| 痛点 | 本技能的做法 |
|---|---|
| 方案写成功能清单，没有诊断过程 | 强制四层链路，未完成"现状+痛点"不许写方案 |
| 每页版式雷同、翻页疲劳 | 五套差异化骨架，相邻页骨架必不同 |
| 找素材图耗时、版权与清晰度不可控 | 26 个原生矢量图标按语义选型，零素材依赖 |
| 文字不齐、溢出、压字，交付靠肉眼 | 真实字体度量自检，交付前必须 0 问题 |
| 换个客户就得重写代码 | 内容与引擎解耦，换客户只改 JSON |

## 二、适用场景（何时调用）

**必触发**：
- 编写某模块的 MES/MOM 专题方案（生产管理 / 生产计划 / 工艺 / 品质 / 仓库 / 设备 / 追溯 / 异常 / 成本）
- 把调研报告、会议纪要、现场录音稿转成结构化方案页
- 客户方案汇报需要 3–10 页的方案页（现状、痛点、方案、价值）
- 需要跨行业方案基线（电子组装 / 装备制造 / 注塑 / 机加工 / 新能源 / 新材料）

**不适用**（走别的技能）：
- 只做图片转 PPT → `more-jpg-to-ppt`
- 多份单页 PPT 合并套模板 → `摩尔多页PPT合并`
- 纯 PPT 美化体检 → `ppt-polish`
- 把临时资料转成 Word 报告 → `moore-temp-to-doc`

**可选增强（甲方要求「方案里要看到系统长什么样」时）**：
在 Step 3 之后追加 **Step 3+ · 系统界面截图弹层**（不改动正文，见 `references/screen-overlay.md`）。
判据：方案区可用高度仅 5.60in、实测五套骨架余量只有 **0.02–0.30in** ——
**正文排满时塞不进可读截图，只能走悬浮弹层**。

## 三、输入要求

**必需（最少）**
1. **客户与行业**：客户名、所属行业（决定套哪套行业基线）。
2. **模块主题**：本次要写哪个业务模块（如"生产管理"）。
3. **素材来源**：调研报告 / 会议纪要 / 客户访谈记录 / 现状系统清单 —— 任一种即可。
   资料越具体（现有系统、线体数量、手工环节、异常频次），痛点与价值越扎实。

**可选（有则更好）**
- ima 知识库中的同类方案素材（本技能可按 `folder_id` 检索，见 `references/env-notes.md`）
- 页数（默认 5 页）、骨架偏好、客户品牌色、必须出现的术语或模块名
- 明确的量化目标（如 OEE 提升 8%、交付达成率 95%）

**资料缺失时的处理**：先按行业基线补齐，但**所有推断值必须在页脚统一声明"行业基准示意口径，正式立项以现场调研数据替换"**，不臆造客户实测数据。

## 四、执行流程（五步，顺序不可颠倒）

### Step 0 · 行业基线对齐
确认客户行业与模块范围，调取该行业 MES 基线（见下表），预设本模块的重点场景。
> 六行业基线：电子组装（SMT/AOI/SN 追溯/防错上料）、装备制造（项目型排产/柔性路线/关键件追溯）、
> 注塑（模具全生命周期/配方称量/回料/啤次）、机加工钣金（DNC/刀具/套裁/外协齐套）、
> 新能源电池（多级追溯/工艺参数强管控/SPC）、新材料（配方版本/批次称重/ECN/边角料回收/成本到批次）。

### Step 1 · 内容成稿（先内容，后版式）
**必须先产出内容 JSON，再谈排版。** 按 `references/methodology.md` 的铁律逐页写：
- 页标题写**结论句**（"构建工厂级统一生产管理体系"），不写栏目名（"需求分析"）。
- 四模块：`need`（4 条业务结果）、`pain`（4 条可归因痛点）、`flow`+`alt`（双视角方案）、`kpis`+`claim`（量化价值）。
- 两视角固定搭配：**① 流程型思维**（端到端流程图，必带 `note` 卡控点/状态机）+ **② 第二视角**
  （系统思维 / 数据驱动 / 标准化 / 供应链协同 / 设备全生命周期，按场景选）。
- 五页默认叙事：P1 体系总览 → P2 计划排产 → P3 工艺品质 → P4 物料追溯 → P5 落地价值。

字段与字数约束见 `references/content-schema.md`；写完后自查方法论第三节「质量红线」6 条。

### Step 2 · 骨架分配（做差异化）
给每页指定 `bone`：默认 `A → B → C → D → E`。相邻两页骨架不得相同；
页标题、四模块顺序、留白节奏随之变化（各自规格见 `references/layout-bones.md`）。

### Step 3 · 生成与体检
```bash
PY="C:/Users/majunpeng/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
SKILL="C:/Users/majunpeng/.workbuddy/skills/摩尔结构化方案编写"

# 自包含模式（沿用技能自带版式/页眉/页脚）
"$PY" "$SKILL/scripts/build_deck.py" <内容.json> --out "<客户名>_<主题>_<n>页.pptx"

# ★ V2.0 模板模式（推荐：客户有统一模板时）
# 封面/目录/封底/过渡页/标题/Logo 位置零改动，仅克隆页眉组 + 套四模块骨架
"$PY" "$SKILL/scripts/build_deck.py" <内容.json> \
      --template "E:/02跟进项目/PPT模板.pptx" \
      --out "<客户名>_<主题>_<n>页_模板版.pptx" \
      [--dividers <分隔页.json>]     # 可选：专题过渡页 {"before":1,"title":"生产管理专题","sub":"PRODUCTION MANAGEMENT"}

# 仅体检
"$PY" "$SKILL/scripts/check_layout.py" "<客户名>_<主题>_<n>页.pptx"
```
**判定标准：`版式问题总数: 0`。** 有溢出时按"砍字 → 换术语 → 降层级 → 才调参数"的顺序修，
改完必须重跑体检（见 `references/content-schema.md` 第三节）。
> 模板模式下封面/封底若仍出现旗标，多为**模板原稿自带**（如用 Arial 制作、字体度量差），
> 属"零改动沿用"的预期表现，非本技能渲染问题。

### Step 3+ · 系统界面截图弹层（可选，甲方要看系统界面时）
**先读 `references/screen-overlay.md`**（几何、动画两个坑、素材筛查全部在那里）。
```bash
# 每页 2–5 张界面截图，点击逐张切换；正文零改动
"$PY" "$SKILL/scripts/add_screens_overlay.py" \
      --src "<客户>_<主题>_<n>页.pptx" --out "<客户>_<主题>_<n>页_系统截图版.pptx" \
      --shots <截图配置.json> --lib <截图目录>

# 动画校验：悬空 spid 必须「无」，点击组数 = 截图张数 + 1
"$PY" "$SKILL/scripts/verify_overlay.py" "<客户>_<主题>_<n>页_系统截图版.pptx"
```
三条硬约束：**说明条 y 必须 < 1.36**（否则体检把它判给底下卡片，误报溢出）·
**同页截图共用同一几何位置**（结构上保证互不遮挡）· **等比 contain 不裁切**（UI 文字就是价值）。
素材优先用【素材集】N2.MOM，但**必须先筛查**：138 张里约一半是产品照片/插画，
且 `L110`–`L118` 是客户案例页（含第三方客户标识），对外汇报一律不用。

### Step 4 · 交付与归档
- **交付**：用 `present_files` 打开生成的 .pptx（必做，不能只给路径）。
- **归档**：交付件与内容 JSON 同目录保存，便于复现与改版；需要进知识库时走
  `ima-knowledge-archive` 技能，命名 `主题-日期-版本`。
- **如实说明**：本机无 PowerPoint/WPS，未做 Office 端渲染验收，仅完成字体度量级版式自检。
- **写工作日志**：`.workbuddy/memory/YYYY-MM-DD.md` 追加一条结论性记录。

## 五、输出规范

**PPT 交付件**
- 格式：16:9 `.pptx`，全矢量（形状 + 文本框），可在 PowerPoint / WPS 中直接改字改色。
- 命名：`客户名_主题_n页.pptx`（例：`绿控传动_生产管理专题方案_5页.pptx`）。
- 结构：每页 = 页眉（页序/标题/副标题）+ 四模块（需求/痛点/双视角方案/价值）+ 页脚（数据来源声明）。
- 版式：五套骨架差异化，配色与字号全篇统一（令牌见 `references/layout-bones.md`）。

**随附产出**
- 内容 JSON（可复现、可改版、可入库检索）
- 版式体检结果（问题数 0）
- 若启用归档：入库条目含标题 / 分类 / 标签 / 一句话摘要

**质量红线**：四模块齐全无占位符 · 痛点可归因 · 双视角齐全且流程层带卡控点 ·
KPI 全为数字或符号 · 版式体检 0 问题 · 页标题即结论。
