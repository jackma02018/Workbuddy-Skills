# 四层价值翻译方法论（方案内容铁律）

> 方案不是功能清单。每一页、每一个场景都必须走完「现状 → 痛点 → 方案 → 价值」四层，
> 缺任何一层都视为未完成诊断。四页 PPT 的位置固定不变（需求 / 痛点 / 方案 / 价值），
> 这样横向翻页时读者永远知道"这一块在哪"。

## 一、四层各自的写法标准

### 第 1 层 · 业务需求（页面左上 / 上栏 / 左栏）
- **写"客户要什么结果"，不写"我们要上什么模块"**。
- 4 条为准，每条 ≤ 20 字，动词开头：统一 / 承接 / 收敛 / 可视 / 可复制 / 可追溯。
- 好的写法：`统一管理语言：8 条线体执行标准一致`
- 坏的写法：`实施 MES 工单管理模块`（这是方案，不是需求）

### 第 2 层 · 当前痛点（页面右下 / 中栏 / 右栏）
- **必须可归因、可量化**，用「痛点短标签 + 可归因描述」两段式。
- 短标签 ≤ 8 字（4 条对齐，视觉上形成节奏）；描述里尽量带数字、系统数量、频次。
- 好的写法：`('系统烟囱林立', '园区自研、吴江自研、外购 3 套并存')`
- 坏的写法：`('管理混乱', '车间比较乱')` —— 笼统形容词等于没写。
- MECE 归类优先落在这五类：**交期 / 成本 / 质量 / 协同 / 合规**，并标注最致命的 1–2 条。

### 第 3 层 · 解决方案（页面右主区 + 中区，占视觉重心）
必须给出**两个视角**，这是本套方法论区别于普通方案页的关键：

| 视角 | 定位 | 呈现组件 | 内容要求 |
|---|---|---|---|
| **① 流程型思维** | 端到端主流程，回答"业务怎么跑" | 横向流程链（flow_h_icon）/ 网格流程（flow_grid_icon）/ 纵向流程（flow_v_icon） | 5–6 步闭环，每步「步骤名 + 一句话说明」，末尾必带 `note` 写明**卡控点或状态机** |
| **② 第二视角** | 解释架构或数据依据，回答"为什么成立" | 图标卡网格（icon_cards）2×2 / 2×3 / 6×1 | 4–6 张卡，每张「图标 key + 标题 + 一句话说明」 |

第二视角按场景选型（不要每页都用同一个）：

| 场景特征 | 推荐第二视角 | 卡片讲什么 |
|---|---|---|
| 系统重构、多系统并存 | **系统思维 / 架构思维** | 分层架构（L3 工厂级 / L2 产线级 / 集成总线 / 建模能力） |
| 排产、调度、交期 | **数据驱动思维** | 要素数据化 / 甘特 / ECT 引擎 / 看板 / 快速转产 |
| 工艺、质量、防错 | **标准化思维 / 闭环思维** | 标准受控 / 卡控点 / 偏差闭环 / 知识沉淀 |
| 物料、追溯、拉动 | **供应链协同思维** | 三级库存 / 齐套 / 拉动信号 / 双向追溯 |
| 设备、OEE、维护 | **设备全生命周期思维** | 联网采集 / 点检保养 / 备件 / OEE 归因 |

- `flow_icons` 必须与 `steps` **等长**，按步骤语义逐个选图标（见 icon-library.md）。
- 严禁只写"实施 XX 模块"这类功能名，必须体现 AS-IS → TO-BE 的断点消除。

### 第 4 层 · 方案价值（页面底部通栏 / 反色带）
- **能写数字就不写形容词**。3–4 项 KPI，每项「数值 + 指标名」。
- 数值写法约定：目标值直接写（`95%`、`≤15min`）、改善幅度写箭头（`↓60%`、`↑12%`）、
  结构性收敛写迁移（`3 → 1`、`1 套`）。
- 配一句 `claim`（≤ 70 字）作结论收口，落在经营语言上：
  统一替代 / 收敛 / 闭环 / 可复制 / 降本增效，而不是"提升管理水平"这类空话。
- 指标口径必须是「行业基准示意」，页脚统一声明数据来源，不臆造客户实测值。

## 二、页面级内容组织模板（五页通用骨架）

| 页 | 主题定位 | 主视觉 | 骨架 |
|---|---|---|---|
| P1 | 总览 / 体系构建：**一套系统替代 N 套** | 端到端主流程横向链 | A |
| P2 | 计划 / 排产：**经验承诺 → 模型测算** | 工单全生命周期状态流 | B |
| P3 | 工艺 / 质量：**过程标准化与防错** | 标准受控 + 卡控闭环 | C |
| P4 | 物料 / 追溯：**齐套与双向追溯** | 三级库存 / 拉动 | D |
| P5 | 综合 / 价值：**落地路径与收益** | 三竖栏聚焦 | E |

页标题写**结论句**，不写栏目名：
- 好：`构建工厂级统一生产管理体系`、`生产工单与有限产能排产闭环`
- 坏：`生产管理需求分析`、`解决方案`

## 三、质量红线（交付前自检）

1. 每页四模块齐全，无空卡片、无占位符文字。
2. 痛点全部可归因（有数字 / 系统名 / 频次），无"混乱、不规范"这类无主语形容词。
3. 方案有且仅有两个视角，流程型思维必带 note（卡控点 / 状态机）。
4. KPI 每项都是数字或符号，`claim` 落在经营收益。
5. 版式体检 0 问题（见 scripts/check_layout.py）。
6. 结论先行：页标题即结论；同一页内信息不重复（需求与痛点不写同一句话）。
