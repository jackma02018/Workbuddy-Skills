# 系统界面截图弹层 + 点击动画（方案 PPT 增强）

在已通过体检的方案 PPT 上追加系统界面截图，**不改动正文**，用「悬浮弹层 + 点击逐张切换」承载。
本文件是这条路子唯一的方法论与规范来源，执行前通读。

---

## 一、何时用 / 何时不用

| 情况 | 做法 |
|---|---|
| 甲方要求「方案页里要能看到系统长什么样」 | ✅ 本方案：每页 2–5 张界面，弹层承载 |
| 方案页本身还有 2in 以上留白 | ✅ 可以改成**页内固定窗口**（不用弹层），截图与流程链同屏 |
| 方案页已排满（本技能产出的页就是） | ✅ 只能走弹层；正文排满时**没有**位置塞入可读截图 |
| 需要导出 PDF / 打印 | ❌ 弹层会叠图。另出「无动画原版」，或按需删弹层后另存 |
| 展台无人值守循环播放 | ❌ 本方案是点击驱动。改成 `afterEffect` + `delay` 自动轮播 |

**先量再决定**：方案区可用高度 = `BOT - TOP` = 5.60in（见 `deck_kit.py`）。
实测五套骨架的方案区余量只有 **0.02–0.30in**，塞不进可读截图 —— 这就是必须走弹层的量化依据。

## 二、几何规范（13.333 × 7.5in 画布）

| 对象 | 位置 / 尺寸 | 说明 |
|---|---|---|
| 弹层面板 | `(1.5667, 1.26)` · `10.20 × 5.74` | 不透明白底，圆角，`0xC8D2DE` 1.25pt 描边 |
| 说明条 | `(1.6667, 1.30)` · `10.00 × 0.36` | **必须在正文区 TOP=1.36 之上** |
| 截图容器 | `10.08 × 5.22`，起点 `y = 1.72` | 等比 contain 居中 |

**三条硬约束**

1. **说明条 y 必须小于 1.36。** `check_layout.py` 把每个文本框判给「第一个完全包含它的卡片」；
   若说明条落在正文区内，会被判给底下的模块卡片，触发「文字溢出卡片」误报。
   放在 1.30 时，包含它的卡片是弹层面板自身 —— 归属合法，体检保持 0 问题。
2. **所有截图共用同一几何位置**（同框叠放）。这是「任一时刻只有 1 张可见」的结构保证，
   不依赖动画可靠性，导出/编辑视图下也只会看到最后一张堆在最上面。
3. **等比 contain，不 cover。** 界面截图的文字信息就是交付价值，裁掉一点就等于废掉一张图。
   容器 10.08×5.22（比例 1.93），16:9 截图按高度适配 → 实显约 **9.28 × 5.22in**，UI 文字可读。

## 三、动画规范

### 分组（n 张截图 → n+1 次点击）

| 点击 | 入场 | 退场 |
|---|---|---|
| 1 | 面板 + 图1 + 说明1 | — |
| 2 … n | 图k + 说明k | 图k-1 + 说明k-1 |
| n+1 | — | 图n + 说明n + 面板 |

第 n+2 次点击正常翻页（本页动画耗尽）。

### 必踩的两个坑

**坑 1 · 同组效果必须是 `clickEffect` + `withEffect`。**
同一次点击内的多个效果，第一个写 `nodeType="clickEffect"`，其余写 `nodeType="withEffect"`。
若全写 `clickEffect`，一次点击只播一个效果 —— 3 张图的页会退化成 14 次点击才能走完。
校验：`verify_overlay.py` 的「点击组」必须等于「截图张数 + 1」。

**坑 2 · 效果本体是 `style.visibility` 的 `p:set`，不是飞入/擦除。**
```xml
<p:par><p:cTn id="N" presetID="1" presetClass="entr" presetSubtype="0"
              fill="hold" nodeType="clickEffect">
  <p:stCondLst><p:cond delay="0"/></p:stCondLst>
  <p:childTnLst><p:set><p:cBhvr>
    <p:cTn id="N+1" dur="1" fill="hold">
      <p:stCondLst><p:cond delay="0"/></p:stCondLst></p:cTn>
    <p:tgtEl><p:spTgt spid="形状ID"/></p:tgtEl>
    <p:attrNameLst><p:attrName>style.visibility</p:attrName></p:attrNameLst>
  </p:cBhvr><p:to><p:strVal val="visible"/></p:strVal></p:to></p:set>
  </p:childTnLst></p:cTn></p:par>
```
`presetClass="entr"` 让 PowerPoint 在动画播放前不显示该形状；退场用 `presetClass="exit"`
+ `val="hidden"`。切换瞬间完成，无位移无缩放，截图始终以最终清晰度呈现。

**坑 3 · 整个 `<p:timing>` 是追加到 `slide._element` 末尾，不是替换。**
原页可能已有 timing（本技能产出的页通常没有），追加前先确认没有同名节点，否则动画树冲突。

### 参考实现
已有一份可运行实现：`~/.workbuddy/skills/.../more-*` 之外，本项目 `_add_overlay.py`（江阴旺达 13 页）是首个落地版，

客户 PPT 抽取 `ppt/slides/slideN.xml` 的 `<p:timing>` 做交叉验证。

## 四、素材来源与筛查（关键，别跳过）

### 4.1 素材池
`【素材集】N2.MOM制造运营管理系统`（工作区里通常位于 03方案编写 或产品资料目录）是首选：
摩尔自有产品界面，**无第三方客户标识**，对外汇报最安全。解包后按 `slideN` 建索引：

```python
# 从 ppt/slides/slideN.xml 抽 <a:t> 文本 + rels 指向的 media 文件，建 slide -> image 映射
# 得到形如：S085 -> [("L085_49f36db2.png", 1774, 874)]  标题="SPC分析-实时监控与评估"
```
把每张图重命名为 `L{slide号}_{hash}.png`，并输出 `_lib_index.txt`（页码 + 标题 + 图名 + 尺寸），
后续选图只查这个索引，不再重复解包。

### 4.2 必做筛查：素材集里约一半不是界面截图
138 张里混有**产品照片、3D 渲染、矢量插画、客户案例照片**。挑图时逐张看一眼，
或用「白底/深底占比 + 颜色数」打分粗筛，但**粗筛只能排序、不能定论**（插画常是白底反而高分），
最终必须过一眼拼版。

典型误选（都被肉眼抓到过）：显微镜照片、轴承零件照片、扫码枪照片、印章插画、
文件夹插画、3D 蓝色箭头、手持平板插画、设备三视图插画。

**判定口径**：画面主体是**窗口/表单/表格/图表/看板**，且能看到菜单、标签页、表格线、
坐标轴等界面构件 → 界面截图；画面主体是实物或插画 → 不用。

### 4.3 避开第三方客户标识
素材集里 `L110`–`L118` 是**客户案例页**（长虹 / 南孚 / 挚达 / 菱电 / 飞荣达 / 海德威 / 中控 / 浪潮），
截图里带客户名、Logo、现场照片。**对外汇报一律不用**，只用 `L003`–`L109` 的产品功能与看板页。

### 4.4 替换而非硬凑
若某张定稿后发现是照片/插画，**换成同主题的界面图**，并同步改说明条文案 ——
说明条文字必须与截图内容对得上，否则现场被追问就露怯。

```bash
      --shots shots.json --lib _lib

"$PY" "$SKILL/scripts/verify_overlay.py" "<客户>_<主题>_13页_系统截图版.pptx"

# 3) 版式体检必须回到 0 问题
"$PY" "$SKILL/scripts/check_layout.py" "<客户>_<主题>_13页_系统截图版.pptx"
```

### 交付时必须一起说清的四件事
1. **放映才生效**：编辑视图/阅读视图下所有截图堆叠可见，必须用「放映」模式。
2. **PDF 会叠图**：需要 PDF 就交付无动画原版。
3. **本机无 PowerPoint/WPS**：只做了字体度量级几何校验与动画引用校验，未做 Office 端渲染验收，
   请客户/同事先放映一遍。
4. **对应关系要成文**：附一份「截图 ↔ 页面 ↔ 讲解落点」对照表（可打印 HTML），
   把「第 k 张对应本页哪一段」写死，汇报人照着点即可。
