# 版式工程规范（栅格 · 设计令牌 · 五套骨架）

> 全部实现在 `scripts/deck_kit.py`。本文件是它的规格说明——换页、换骨架、判断
> "内容往哪个组件里塞"时先读这里，不要改引擎。

## 一、画布与栅格

| 项 | 值 |
|---|---|
| 画布 | 13.333 × 7.5 in（16:9），`SW, SH` |
| 页边距 | `MARGIN = 0.50` |
| 栏间距 | `GUT = 0.16` |
| 版心宽 | `CONT_W = 12.333` |
| 栏宽 | `COL_W = (CONT_W - 11*GUT) / 12 = 0.881` |
| 正文区 | `TOP = 1.36`，`BOT = 6.96`，`BODY_H = 5.60` |
| 页眉带 | 0 → 1.05（顶部 0.10 为四色进度条） |
| 页脚 | 7.06 分隔线 + 7.14 文字 |

取栏位一律用 `cx(起始栏)` / `cw(跨栏数)`，**不要手写坐标**：
`cx(5) = 0.50 + 5*(0.881+0.16)`；`cw(7) = 7*0.881 + 6*0.16`。

## 二、设计令牌（配色 / 字体）

| 令牌 | 色值 | 语义 | 用在哪 |
|---|---|---|---|
| `C_NEED` | `1F6FEB` 蓝 | 业务需求 | 需求卡头部、页眉色条 1 |
| `C_PAIN` | `D9534F` 红 | 当前痛点 | 痛点卡头部、页眉色条 2 |
| `C_SOLVE` | `0B7285` 青 | 解决方案 | 流程链节点、流程卡、页眉色条 3 |
| `C_VALUE` | `D97706` 橙 | 方案价值 | 底部价值带、KPI 数字、页眉色条 4 |
| `NAVY` | `143354` | 页眉底 | 页眉带 |
| `INK` / `TXT` | `0F2740` / `334252` | 主 / 次正文 | 标题、正文 |
| `GREY` / `GREY2` | `6B7A8C` / `9AA7B4` | 辅助 / 极淡 | 说明文字、页脚 |
| `BG` / `PANEL` | `F4F6F9` / `FAFBFC` | 页面底 / 面板底 | 背景层 |
| `LINE` / `SEPL` | `E4E9F0` / `EEF1F5` | 边框 / 分隔 | 卡片描边、栏间分隔 |

字体统一 **微软雅黑**（`FONT`）。字号梯度：页标题 21 / 页序 24 / 卡片标题 11–12 /
正文 8.5–9.5 / 说明 7–8 / 页脚 7.5。**同一层级全篇字号一致，不随页面变。**

配色铁律：四色语义固定，**不得为了"好看"换色**；一页内不超过 4 个主色 + 3 个中性色。

## 三、五套页面骨架

调用方式：`BONES['A'][0](slide, content_dict)`，或直接用 `build_deck.py` 按 JSON 的 `bone` 字段路由。

| 骨架 | 结构 | 主视觉位置 | 适合内容定位 |
|---|---|---|---|
| **A** | 右重双栏 5:7 + 底部通栏价值带 | 右栏（7 栏）横向流程链 | 总览、体系、架构收敛类；横向链条叙事 |
| **B** | 上通栏 + 下三栏 5:4:3 | 上通栏横向流程 + 右栏第二视角 | 计划、排产、闭环状态流类；先横向后拆解 |
| **C** | 上条 + 中 4:8 + 底 8:4 | 中区（8 栏）网格流程 + 六宫格第二视角 | 工艺、质量、防错类；标准与卡控并重 |
| **D** | 双塔竖切 左三段 : 右通高 6:6 | 左栏纵向流程 + 左栏第二视角；右侧通高 | 物料、追溯类；左右对望、并行对比 |
| **E** | 三竖栏 3:6:3 + 底部反色带 | 中栏（6 栏）网格流程 + 图标卡 | 综合、价值、路径类；剧场式中庭聚焦 |

**差异化是硬指标**：同一份 PPT 里相邻两页必须不同骨架。默认序列 `A → B → C → D → E`
（`bone` 字段可自由指定、可重复，但连续重复会削弱翻页节奏）。

**第二视角卡片数量上限（实测）**：`alt.cards` 虽容许 4–6 张，但各骨架的中区高度不同——

| 骨架 | 卡片列数 | 可容纳上限 | 说明 |
|---|---|---|---|
| **A / E** | 2 列 | **最多 4 张** | 5 张排 3 行，末行必越出面板（文本底 ≈6.05 > 卡片底 5.91） |
| B / C / D | 2 列 | 5–6 张 | 下区/中区更高，5 张两行半可容纳；C 为纯标签宫格 |

写内容时若在 A/E 页想要 5 张卡，**合并两张语义相近的卡**（例：`SPC 管制图` + `CPK 与良率分析`），
不要缩字号。多专题合并成一份 PPT 时尤其容易踩到——某专题单页无问题，换骨架后即溢出。

各骨架的价值带形态也不同（避免"每页底部都一样"）：
A 横带（标题+KPI）、B 三栏底（需求/价值/风险式）、C 双区底（8:4）、D 右通高、
E 反色带（深底 + 高亮数字）。

## 四、组件库（往内容里放什么）

| 组件 | 用途 | 内容形态 |
|---|---|---|
| `card` | 卡片容器（带彩色头带 + 中英文小标） | 四个固定模块的容器 |
| `chip` | 小色块标签 | pain 短标签底 |
| `icon` + `glyph` | 矢量图标徽章（圆角底 + 图形） | 26 个 key，见 icon-library.md |
| `flow_h_icon` | 横向流程链（带箭头） | 端到端主流程，5–6 步 |
| `flow_grid_icon` | 网格流程（2–3 列） | 步骤较多或中区较窄时 |
| `flow_v_icon` | 纵向流程（左栏竖排） | 骨架 D 左栏 |
| `icon_cards` | 图标卡网格 | 第二视角卡片 |
| `kpi_grid` / 价值带 KPI | 指标组 | 3–4 项 |
| `panel_head` | 子面板标题（含英文副标题） | 两个视角的头部 |
| `note_bar` | 卡控点 / 状态机提示条 | 流程层收口 |
| `table`（看板场景） | 明细表 | 仅在管理看板类页面使用 |

## 五、响应式与输出介质

同一份内容按介质换版式，不换配色与字体：

| 介质 | 画布 | 调整 |
|---|---|---|
| 16:9 汇报（基准） | 13.333 × 7.5 | 如上 |
| 4:3 投影 | 10 × 7.5 | 骨架 A/D 收窄为单列堆叠，流程链转 `flow_grid_icon` 2 列 |
| 9:16 长图 / 手机 | 7.5 × 13.333 | 骨架全部转纵向：需求→痛点→方案→价值 顺序堆叠，流程链转 `flow_v_icon` |
| A4 打印 PDF | 21 × 29.7 cm | 保留 16:9 页 + 每页独立分页，页脚补页码与密级 |

移动端断点（HTML 版同样内容）：
- ≥1200px：保持 12 栏栅格
- 768–1199px：栅格降为 6 栏，双栏转上下堆叠
- <768px：单栏，KPI 一行 2 个，流程链转纵向

## 六、版式自检（必做）

```bash
<PY> scripts/check_layout.py <生成的.pptx>
# 输出「版式问题总数: 0」才算通过
```

检查三类问题：① 文本溢出自身文本框；② 文本越出所属卡片（含右侧越界）；③ 越出页面。
判定基于 PIL + `C:/Windows/Fonts/msyh.ttc` 的真实字体度量（不是估算）。
发现溢出时：**先缩文案字数，再调字号，最后才动骨架参数**——顺序不要反。
