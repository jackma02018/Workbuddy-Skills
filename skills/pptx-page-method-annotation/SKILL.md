# PPTX 逐页汇报方法论标注 与 标题价值化改写

把一份「素材库式」PPT 从「内容集合」升级为「可汇报的武器库」：每一页都明确该用什么方法论讲、怎么拆、讲到什么落点，并且**标题一眼就能看出核心价值**。

本技能含两条独立可单跑的流水线：

- **A 线｜方法论标注**：逐页判定 SCQA/FAB/BACC/PREP → 写备注 → 出索引。
- **B 线｜标题改写**：逐页改写标题为「结论先行＋价值显性」 → 出对照表。

两线可串联（A 线产出「备注版」，B 线在备注版基础上另存为「话术优化版」，备注完整保留）。

## 适用场景

- 方案素材库 / 复用型 PPT，页数多（几十到几百页），客户名混杂，需要标准化汇报话术。
- 售前顾问拿到别人的方案库，需要快速搞清楚「每页该怎么讲」。
- 方案评审前，需要给每页补齐结构化拆解以便他人照读汇报。
- 标题写得像目录（「生产计划:生产计划下推生产制令单到车间线体，通过甘特图等方式掌控生产进度」），客户扫一眼抓不到价值，需要改成「一眼看懂」的标题。

## 不适用

- 生成新 PPT（那是 `tencent-pptx` / `摩尔结构化方案编写` 的职责）。
- 只做排版美化（那是 `ppt-polish` 的职责）。

## 四套方法论的判定规则（核心资产）

这是本技能最有价值的部分。判定不靠感觉，靠页面特征。

### SCQA — 适用于「诊断 / 对标 / 场景」类页面

**判定特征（满足任一即优先 SCQA）**：

| 特征 | 例子 |
| --- | --- |
| 页面含客户现状描述 | 苏州百胜需求以及改善方向 |
| 含痛点、问题清单 | 钣金车间当前作业流程及管理需求与痛点 |
| 含标准/模型对标 | 智能制造能力成熟度评估模型（GB/T 39116） |
| 含蓝图、架构、总览图 | 智能工厂整体蓝图规划、全业务价值流管控总览 |
| 含规划分期、路线图 | 智能工厂建设 3 年规划建议 |
| 含流程闭环 + 前后对比 | 旧系统切换流程、NC 程序版本管控 |
| 含成本/价值反算 | 成本核算、成品型转 |
| 面向决策层讲「为什么做」 | 智能工厂定义、系统集成收口 |

**拆解四要素**：
- **S 情景**：客户当前客观状态（业务模式、已上系统、组织、产品工艺），只陈述事实，不带评价。
- **C 冲突**：现状与目标之间的张力。写法要点：**痛点要成组**（不是罗列，是归因），最好点出「痛点互相放大」（如账不准→计划乱→交付差）。
- **Q 问题**：客户真正的疑问，要用客户会问出口的原话。如「凭什么相信你能做？」「先改什么后改什么？」「要花多少钱、多久见效？」
- **A 答案/价值**：方案机制 + 落到具体角色/数字的收益。

### FAB — 适用于「功能 / 机制 / 场景化功能」类页面

**判定特征**：页面主体是一个具体功能或机制（上料防错、烘烤管控、技能矩阵、ESOP、维修闭环、Andon……），信息结构为「功能清单 + 实现方案 + 实现价值」。

**拆解三要素**：
- **F 属性/功能**：系统具体做什么，把页面上的功能点原样归纳，保留参数（如金线线径 0.9/1.0/1.2mm、烘烤温度时长、复检周期）。
- **A 优势**：与「靠人管」相比的机制优势。写法要点：**强调机制而非功能**——「未扫码锁轨道」「过期程序自动拦截」「不点检不让开工」「系统校验不足8小时不允许提交」。
- **B 利益**：客户拿到什么。能用数字就用数字（换线 15–30 分钟→30 秒、新员工上岗周期缩短 50%）。

### PREP — 适用于「架构 / 流程 / 清单 / 方案枚举」类页面

**判定特征**：页面是分层架构、流程步骤、功能清单、方案对比清单、参数表格。

| 特征 | 例子 |
| --- | --- |
| 分层架构图 | WMS 系统业务功能架构 |
| 流程步骤（有明确顺序） | 旧系统切换流程、产品收尾报告四步 |
| 功能清单/参数表 | 胶管车间工序管控点表 |
| 多方案并列枚举 | 四个工时采集方案（RFID/AI视觉/红外/三色灯） |
| 手顺、作业指导类 | 拉丝产出、入线边库 |

**拆解四要素**：
- **P 结论**：一句话说清这页的机制是什么。
- **R 理由**：分条列出支撑（①②③），每条落到具体机制。
- **E 例证**：页面上的具体数据、表格、参数、流程节点。
- **P 结论复述**：价值收口，一句话。

### BACC — 适用于「方案选型 / 帮客户做决策」类页面

**判定特征**：页面上并列多个候选方案，带风险/难度/推荐度等评价维度，客户需要在其中选一个。

**拆解四要素**：B 背景 → A 行动 → C 结果 → C 结论/建议。

**关键提醒**：BACC 页面汇报时**必须给出你的推荐及理由**，否则客户会反问「那你建议哪个」，节奏立刻被动。

## 工作流程

### Step 1 — 全量内容提取（不要逐页 Read PPT）

用 python-pptx 递归遍历（必须处理 GroupShape，否则漏掉组合里的文字），导出为「每页标题 + 聚合正文 + 现有备注」的纯文本概要，再分批 Read 概要文件。

```python
def collect(shapes, texts):
    for sh in shapes:
        if sh.__class__.__name__ == 'GroupShape':
            collect(sh.shapes, texts); continue
        if sh.has_text_frame and sh.text_frame.text.strip():
            texts.append((sh.name, sh.text_frame.text.strip()))
        if getattr(sh, 'has_table', False) and sh.has_table:
            rows = [" | ".join(c.text.replace("\n"," ").strip() for c in r.cells)
                    for r in sh.table.rows]
            texts.append(("TABLE", "\n".join(rows)))
```

标题识别规则：优先取 shape.name 含「标题」的文本框，否则取最靠上的文本框。

**注意**：内容可能很大（本例 112 页 → 33 万字符全量、约 3500 行概要）。先导出到文件，再分 400–600 行一批 Read，不要试图一次读完。

页面结构速判技巧：素材库 PPT 常在底部/右侧有固定的「章节导航条」（本例为「生产计划/生产与仓库协同/产前准备/…/主机厂稽核」），这是**模板固定元素**，不要写进拆解内容里。

### Step 2 — 逐页定义拆解

把全部拆解写成一个 `P[索引] = note(...)` 字典（索引 0 起），用一个 `note()` 函数统一格式。**必须在脚本里断言页数与字典长度一致**，避免漏页。

备注格式（纯文本 + 段首标记，保证 WPS/PPT 备注窗格直接可读）：

```
【推荐汇报方式】FAB（一句话说明为什么用这个方法）

F 属性/功能｜……
A 优势｜……
B 利益｜……

※ 汇报提示｜……
```

「汇报提示」是本技能的增值点，写的是**汇报技巧而非内容**，例如：
- 「不要逐张念证书，用一句话收口到『自研、可控、可长期服务』，控制在 30 秒内」
- 「接口类页面的汇报技巧：不要讲技术细节，讲『四步握手』这个比喻」
- 「必须处理项：空页会打断节奏，建议直接删除」

### Step 3 — 写入备注页

```python
slide.notes_slide.notes_text_frame.text = txt
prs.save(DST)
```

**铁律**：写入备注只改 `notesSlides`，不动 slides。保存后必须校验。

### Step 4 — 结构零改动校验（不可省略）

```python
def stat(p):
    d = {"slides": 0, "shapes": 0, "pics": 0, "tables": 0, "groups": 0, "chars": 0}
    for s in Presentation(p).slides:
        def walk(shapes):
            for sh in shapes:
                d["shapes"] += 1
                if sh.__class__.__name__ == 'GroupShape':
                    d["groups"] += 1; walk(sh.shapes); continue
                if sh.shape_type == 13: d["pics"] += 1
                if getattr(sh,'has_table',False) and sh.has_table: d["tables"] += 1
                if sh.has_text_frame: d["chars"] += len(sh.text_frame.text)
        walk(s.shapes)
    return d
```

原文件与产出文件逐项对比，**全部必须相等**。同时用 zipfile 比对 `ppt/media/` 数量（注意：namelist 里的 `ppt/media/` 目录条目本身可能有无差异，需用集合差集确认实际文件零缺失）。

### Step 5 — 生成索引文档

从产出 PPT 反读备注，正则 `【推荐汇报方式】(.+)` 提取方法，生成 Markdown：

1. 方法分布统计表。
2. 逐页明细表：`| 页码 | 页面主题 | 推荐汇报方式 |`。

这份索引是用户实际翻阅时的对照表，也是后续汇报节奏规划的依据。

### Step 6 — 输出「素材库问题清单」

素材库类 PPT 一定有结构性问题，这是高价值副产品。**必须主动检查并报告**：

- **重复页**：同一方案不同客户版。识别信号是页面主体文字高度相似（仅客户名不同）。例：本例 P12/P16/P17 三度重复、P26/P27/P29 三度重复。
- **空页**：无任何有效内容，汇报时会打断节奏。
- **方法失衡**：若某方法占比 > 50%，说明页面类型单一，或判定需复核。
- **修改建议**：给出「合并为通用方案页 + 客户差异化示例」的建议，并估算瘦身后页数。

## B 线｜标题价值化改写

### 改写公式（核心资产）

```
新标题 = 原编号前缀 ＋ 对象/页型 ＋ 做法（怎么实现） ＋ 可量化结果（省了多少、防住了什么）
```

四条硬性要求：

1. **保留原编号前缀与层级**，一字不动：`1.`、`3.3.`、`一阶段-`、`方案A：`、`四、`。破坏编号会打乱整本 PPT 的目录体系。
2. **结论先行**：先给判断/结果，再给支撑。不要写成「功能描述」。
3. **价值显性**：必须出现「客户能感知的变化」——数字（5 张工单、30 秒、三账合一）、防错（杜绝错号错量、非法流转拦截）、替代（替代人工上报、不点检不让开工）。
4. **控制在原宽度内**：见下方「溢出控制」。

改写对照示例（真实效果）：

| 原标题（目录式） | 新标题（价值式） |
| --- | --- |
| 生产计划:生产工单下推到生产车间，以产品类型精简工单数量，支持甘特图等方式掌控生产进度 | 奥福环保工单精简：原料到成品仅5张工单，管住超产并保留实验工单 |
| 生产工单-车间即时呈现各个工序生产进度，避免超产与生产进度不上等问题 | 生产工单车间即时可视：多端无纸化下达，异常自动预警替代人工上报 |
| 解决方案（车间排产衔接）- 构建产销衔接、敏捷交付的计划体系 | 解决方案（车间排产衔接）：订单流·排产流·物料流三线贯通，精准交付 |
| 备品备件管理 | 备品备件管理：寿命监控与更换提醒，由坏了再换变该换才换 |
| 成本核算 | 成本核算：MES与ERP整合，以工单为维度做到投料产出可算 |

注意末两例：原标题只有 6–8 字（信息量不足），同样需要扩容成完整价值句——**标题改写是双向的，短标题补价值、长标题压冗余**。

### Step B1 — 定位标题框（两个必踩的坑）

**坑 1：标题框名可能不含「标题」二字。**

素材库 PPT 命名混乱，实测出现过 `标题 1`、`標題 1`（繁体）、`TextBox 46`（英文）。查找键必须包含三者：

```python
NAME_KEYS = ("标题", "標題", "TextBox")
```

**坑 2：标题框常在 GroupShape 内，此时 `shape.top` 返回 `None`。**

绝不能用 `if sh.top is None: continue` 过滤（这一条导致首轮 20 页静默漏改）。必须递归展开组合并累加父级坐标：

```python
EMU = 914400
SLIDE_W = 13.333   # 16:9 幻灯片宽（英寸）
RIGHT = 0.15       # 右侧安全留白

def flatten(shapes, ox=0, oy=0):
    """递归展开组合，产出 (shape, 绝对left, 绝对top, width)"""
    out = []
    for sh in shapes:
        L = ox + (sh.left or 0)
        T = oy + (sh.top or 0)
        if sh.__class__.__name__ == "GroupShape":
            try:
                out.extend(flatten(sh.shapes, L, T))
            except Exception:
                pass
            continue
        out.append((sh, L, T, sh.width or 0))
    return out

def find_title(slide):
    items = flatten(slide.shapes)
    txt = [(sh, L, T, W) for (sh, L, T, W) in items
           if sh.has_text_frame and sh.text_frame.text.strip()]
    named = [(sh, L, T, W) for (sh, L, T, W) in txt
             if any(k in sh.name for k in NAME_KEYS)]
    for sh, L, T, W in named:            # 命名命中 + 位于顶部 → 最可信
        if T / EMU < 1.0:
            return sh, L / EMU, T / EMU
    if named:
        sh, L, T, W = named[0]
        return sh, L / EMU, T / EMU
    top_c = [(sh, L, T, W) for (sh, L, T, W) in txt if T / EMU < 1.0]
    if top_c:                            # 兜底：最靠上
        sh, L, T, W = sorted(top_c, key=lambda x: (x[2], -x[3]))[0]
        return sh, L / EMU, T / EMU
    return None, None, None
```

### Step B2 — 溢出控制（基准选错就白做）

**核心陷阱：不能用「标题框宽度」当基准。** 素材库标题框大量使用 `auto_size = SHAPE_TO_FIT_TEXT`（形状自适应文字），文本框会随文字自动加宽，其声明宽度与最终渲染宽度无关。用框宽估算会得出 228%、219% 这种假超限。

正确基准是**标题左边界到幻灯片右缘的可用宽度**：

```python
def measure(shape, left_in):
    t = shape.text_frame.text.replace("\n", "")
    pt = None
    for p in shape.text_frame.paragraphs:
        for r in p.runs:
            if r.font.size:
                pt = r.font.size.pt; break
        if pt: break
    pt = pt or 18.0                                   # 无显式字号时按 18pt
    avail = max(SLIDE_W - left_in - RIGHT, 1.0)        # ← 正确基准
    # 中文 1.0em / ASCII 0.55em 的粗略宽度模型
    est = sum(1.0 if ord(c) > 0x2E80 else 0.55 for c in t) * (pt / 72)
    return t, pt, avail, est, est / avail
```

阈值取 **0.88**（预留边距与字体回退余量）。超限页自动截断并加省略号（`…`），保留前缀。

### Step B3 — 只改文字、保格式

**绝不能**清空 text_frame 重建，那会丢失字体、颜色、字号。正确做法：只替换第一个 run 的文本，删掉多余 run 与多余段落：

```python
def set_title_text(shape, new_text):
    tf = shape.text_frame
    p0 = tf.paragraphs[0]
    runs = p0.runs
    if runs:
        runs[0].text = new_text                       # 保留 run 的 rPr 格式
        for r in runs[1:]:
            r._r.getparent().remove(r._r)
    else:
        p0.text = new_text
    for p in tf.paragraphs[1:]:                       # 标题只保留一段
        p._p.getparent().remove(p._p)
```

### Step B4 — 校验与对照表

1. 结构零改动校验（复用 Step 4 的 `stat()`）：slides / shapes / pics / tables / groups **必须全等**；`textchars` 会变化（标题字数变了），属预期，需单独说明。
2. 媒体文件集合比对（zipfile），零缺失。
3. 复核「超出阈值页数 = 0」。
4. 生成对照表 `<原名>标题改写对照表.md`：`| 页 | 方法论 | 原标题 | 新标题 | 宽度占用 |`。方法论列可从 A 线的索引文档正则回读（注意索引行是 `| P1 |` 带 `P` 前缀，正则别写漏）。

## 陷阱清单

1. **GroupShape 不递归 → 漏内容**。PPT 里大量文字藏在组合内，必须处理。
2. **模板固定元素混入内容**。章节导航条、Logo、页码不要写进拆解。
3. **备注格式不能带 Markdown 语法**。PPT 备注窗格不渲染 `**`、`#`，只用纯文本 + 段首标记 + 自然缩进。
4. **不能只写方法名**。用户要的是「拆解出来」——四要素必须逐条写实，不能写成「S 情景：客户现状」这样的占位符。
5. **不能遗漏空页**。空页也要给一条备注（说明是空页 + 建议删除），保证备注覆盖率 100%，便于校验。
6. **标题框名不含「标题」二字**。必须兼容 `TextBox`（英文命名），否则静默漏改。
7. **组合内 `shape.top is None`**。绝对坐标必须靠 `flatten()` 累加父级求出，禁止用 `None` 判断跳过。
8. **溢出基准不能用标题框宽度**。多数标题框是 `SHAPE_TO_FIT_TEXT`，须用「到幻灯片右缘的可用宽度」。
9. **改写标题不要重建 text_frame**。只改 run 文本，保住字体/颜色/字号。
10. **改写标题要保留原编号前缀**。删掉 `1.`、`一阶段-` 会打乱目录体系。
11. **本机无 Office**。交付时如实说明未做 Office 端渲染验收。
